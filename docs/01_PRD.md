# PRD — 현장별 공정·기성 대시보드

## 한눈에 보기

- 본사 공무팀 담당자가 매달 12개 가상 현장의 공정·기성 자료를 한 화면에서 비교하는 PC 웹 앱입니다.
- 첫 화면은 점검이 필요한 현장 순위이며, 맨 위에 전체 기성률·공정률 큰 숫자 한 줄을 함께 보여 줍니다.
- 자료 가져오기, 현황 보기, 점검 현장 찾기, CSV 내보내기, AI에게 묻기 5가지 기능을 만듭니다.
- 로그인, 데이터베이스, 일정 예측은 만들지 않습니다. 모든 자료는 교육용 가상 데이터입니다.
- 성공 기준은 이 문서의 "정답 숫자" 표와 같은 결과가 화면에 나오는 것입니다.

---

## 1. 누가·언제·왜 쓰는지

| 항목 | 내용 | 정한 이유 |
|---|---|---|
| 쓰는 사람 | 본사 공무팀 담당자 (추천 수용) | 12개 현장 자료를 모아 가져오고, 필터로 비교하고, CSV로 내보내는 기능이 이 사용 방식과 가장 잘 맞습니다. |
| 쓰는 때 | 매달 현장 자료를 모아 보고할 때 | 자료의 한 행이 "한 현장의 한 달 월말 상태"이므로 월 단위로 사용합니다. |
| 쓰는 이유 | 현장별 공정·기성 현황을 확인하고, 계획보다 늦어진 현장을 찾아 보고하기 위해서 | 공정차이(실제 − 계획)로 점검 대상을 자동으로 가려내면 사람이 일일이 계산하지 않아도 됩니다. |

## 2. 줄이고 싶은 불편

| 항목 | 내용 | 정한 이유 |
|---|---|---|
| 가장 먼저 줄일 불편 | 현장별 엑셀을 하나씩 비교하는 시간 (추천 수용) | 현장 12곳이 각각 다른 파일에 있으면 한 곳씩 열어 비교해야 합니다. 12곳을 한 화면과 한 표에서 보면 이 시간이 줄어듭니다. |
| 함께 줄어드는 것 | 손으로 계산하다 생기는 실수 | 기성률·공정차이·상태는 프로그램이 계산합니다. 원본 자료에 이 값을 중복 저장하지 않습니다. |

## 3. 만들 기능

| 번호 | 기능 | 사용자가 할 수 있는 일 | 정한 이유 |
|---|---|---|---|
| 1 | 자료 가져오기 | CSV 또는 JSON 파일을 고르면 프로그램이 검사하고 미리 보여 줍니다. 확인하면 전체를 바꿉니다. 오류가 있거나 취소하면 지금 자료를 그대로 둡니다. CSV 다음에 같은 JSON을 가져와도 144행입니다(288행으로 쌓지 않음). | 잘못된 파일이 들어와도 기존 정상 자료가 망가지지 않아야 합니다. |
| 2 | 현황 보기 | 처음에는 2026년 9월·전체 현장을 보여 줍니다. 월·지역·공사 유형·현장을 고를 수 있습니다. 전체 기성률, 계획·실제 공정률, 공정차이를 큰 숫자로 보여 줍니다. 선택 월까지의 계획·실제 공정률 추이와 월별 기성 막대도 보여 줍니다. | 가장 최근 월의 전체 상태와 그 흐름을 함께 봐야 보고할 수 있습니다. |
| 3 | 점검 현장 찾기 | 공정차이가 −5pp 이하인 현장을 점검 순위로 보여 줍니다. 현장별 비교표에서 지역·유형·당월 주요 공종을 보고, 행을 펼치면 공사기간·기록된 상황·대응 계획이 열립니다. | 숫자만으로는 이유를 알 수 없으므로, 기록된 상황과 대응 계획을 같은 자리에서 읽을 수 있어야 합니다. |
| 4 | CSV 내보내기 | 지금 고른 월·지역·유형·현장과 같은 범위를 내려받습니다. 원본 15개 열에 기성률·공정차이·상태·당월기성액 4개 열을 더합니다. 숫자와 단위는 그대로 두고, 엑셀에서 한글이 깨지지 않게 합니다. | 엑셀에서 더 계산하는 용도(질문 6, 추천 수용)이므로 계산된 값이 열로 들어 있어야 합니다. |
| 5 | AI에게 묻기 | 질문을 입력하면 AI(Gemini)가 프로그램이 계산한 숫자와 기록된 상황·대응 계획을 근거로 설명합니다. 답변에 기준 월·현장·근거 숫자·참고한 기록 필드를 함께 보여 줍니다. 필터를 바꾸면 이전 답변을 지웁니다. | AI가 숫자를 직접 계산하면 틀릴 수 있으므로 계산은 프로그램이 하고 AI는 설명만 맡습니다. |

### 점검 현장 순위의 한 줄 (질문 4·5, 추천 수용)

| 항목 | 내용 | 정한 이유 |
|---|---|---|
| 한 줄에 보여 줄 숫자 | 현장 ID와 이름, 계획 공정률, 실제 공정률, 공정차이, 기성률 | 계획·실제·기성률을 모두 보여 주면 "공정은 늦었는데 기성은 어떤가"를 한 줄에서 비교할 수 있습니다. |
| 예시 | D · 계획 86.5% · 실제 75.8% · 차이 −10.7pp · 기성률 69.4% | 2026년 9월 D의 실제 계산값입니다. |
| 한 줄을 누르면 | 현장별 비교표로 이동해 그 현장 줄을 강조하고 기록을 펼칩니다. | 순위에서 이유 확인까지 한 번에 이어집니다. 별도 상세 페이지는 만들지 않습니다. |

### 상태 판정 기준

| 상태 | 공정차이(실제 − 계획) | 점검 순서 |
|---|---|---|
| 점검 | −5pp 이하 | 공정차이가 작은 순, 같으면 현장 ID 순 |
| 주의 | −5pp 초과, 0pp 미만 | — |
| 정상 | 0pp 이상 | — |

이 기준은 교육용 규칙이며 동일토건의 공식 관리 기준이 아닙니다.

### AI에게 묻기의 예시 질문 (질문 7, 추천 수용 / AI 결정)

| 예시 질문 | 정한 이유 |
|---|---|
| D가 늦어진 원인과 대응은? | 점검 이유와 기록된 대응을 설명받는 가장 대표적인 질문입니다. |
| 9월 점검 현장은 어디인가요? | 계산된 점검 순서(D → I → K)가 AI 답변에도 같게 나오는지 확인합니다. |
| D는 회복 중인가요? | 8월 −11.2pp에서 9월 −10.7pp로 줄어든 추이 질문입니다. |
| 실제 준공일·미수금은? | 자료에 없는 내용은 "자료 없음"으로 답하는지 확인합니다. |

## 4. 만들지 않는 것

| 항목 | 정한 이유 |
|---|---|
| 로그인, 데이터베이스, 회사 시스템 연동 | 이번 실습은 파일을 브라우저에서 읽고 계산하는 범위입니다. |
| 실제 기성 청구·발주 | 자료에 청구액·수금액이 없고, 가상 자료입니다. |
| 일정 예측 | 계약상 준공일은 예정 일정이며 실제 완료일을 예측한 값이 아닙니다. |
| 새로고침 후 자료 유지 | 서버 저장이 없으므로 새로고침하면 파일을 다시 가져옵니다. |
| 별도 현장 상세 페이지 | 펼침 행으로 같은 페이지에서 기록을 봅니다. |
| 실제 회사의 계약·현장 정보로 소개하는 것 | 모든 현장명과 숫자는 가상입니다. |

## 5. 수업 후 해 볼 것

| 항목 | 설명 |
|---|---|
| 새로고침 후 자료 유지 | 저장 방식(데이터베이스 등)이 필요합니다. |
| 일정 예측 | 계약상 준공일이 아닌 예상 완료일 계산이 필요합니다. |
| 로그인과 권한 | 사용자별로 볼 수 있는 현장을 나눌 수 있습니다. |
| 청구액·수금액·미수금 자료 연동 | 누적기성액과 구분되는 별도 자료가 필요합니다. |
| 실제 기성 청구 기능 | 가상 자료가 아닌 실제 계약 자료와 승인 절차가 필요합니다. |

## 6. 성공 기준

성공 기준은 따로 정하지 않고, 다 만든 뒤 아래 숫자와 같은 결과가 화면에 나오는 것입니다. 정한 이유: 숫자가 같은지는 누구나 화면에서 바로 확인할 수 있습니다.

| 확인할 것 | 정답 |
|---|---|
| 9월 전체 | 계약금액 630,700 · 누적기성액 424,063.4(백만원) · 기성률 67.2% |
| 9월 공정률 | 계획 73.2% · 실제 71.2% · 공정차이 −2.0pp |
| 9월 당월기성액 | 28,878.7백만원 |
| 8월 전체 | 누적기성액 395,184.7 · 기성률 62.7% |
| 7월 전체 | 누적기성액 364,718.5 · 기성률 57.8% |
| 9월 점검 순서 | D(−10.7pp) → I(−7.6pp) → K(−5.4pp) |
| 9월 상태 내역 | 정상 6곳 · 주의 3곳 · 점검 3곳 |
| 9월 D | 기성률 69.4%, D만 CSV로 내보내면 데이터 1행 |
| 9월 인천·공동주택 | A·G 2곳, 내보내기 데이터 2행 |
| 2025-10 | 당월기성액 "계산 불가", 누적액을 당월액으로 대신하지 않음 (CSV에서는 빈칸) |
| J의 7월 | 당월기성액 0.0, 기록상 기성 확인 서류 보완 |
| 오류 파일 3종 | 모두 거부, 지금 자료 유지 |
| 'D가 늦어진 원인과 대응은?' | 공급 정상화 후에도 남은 지연과 주간 확인 계획을 기록대로 설명 |
| '실제 준공일·미수금은?' | 자료 없음, 계약상 준공일과 실제 완료일을 구분 |

## 7. 이 PRD에서 정한 방식

| 질문 | 답 | 표시 |
|---|---|---|
| 1. 이 화면을 주로 누가 쓰나요? | A. 본사 공무팀 담당자 | (추천 수용) |
| 2. 가장 먼저 줄이고 싶은 불편은? | A. 현장별 엑셀을 하나씩 비교하는 시간 | (추천 수용) |
| 3. 첫 화면에서 가장 먼저 보여 줄 것은? | A. 점검이 필요한 현장 순위 (위에 큰 숫자 한 줄) | (추천 수용) |
| 4. 점검 현장 한 줄에 함께 보여 줄 숫자는? | C. 계획·실제 공정률과 기성률 모두 | (추천 수용) |
| 5. 점검 현장 한 줄을 누르면? | A. 현장별 비교표로 가서 그 현장 줄을 강조하고 기록을 펼침 | (추천 수용) |
| 6. 내려받은 CSV를 주로 어디에 쓰나요? | B. 엑셀에서 더 계산 (원본 열에 기성률·공정차이·상태·당월기성액 열 추가) | (추천 수용) |
| 7. AI에게 주로 무엇을 묻게 될까요? | A. 점검 이유와 기록된 대응 설명 | (추천 수용) |

AI가 정한 항목: AI 예시 질문 4개, 첫 달 당월기성액의 CSV 빈칸 처리 (AI 결정)

## 화면 요약

디자인 도구(Google Stitch)에 그대로 붙여 넣을 수 있는 요약입니다.

1. 페이지 4개: 현황 요약(첫 화면) / 현장별 비교표 / 자료 가져오기 / AI에게 묻기. 상태 화면 5개: 자료 없음 / 가져오기 오류 / 점검 대상 없음 / AI 답변 기다리는 중 / AI 연결 실패.
2. 현황 요약 순서: 월·지역·유형·현장 선택 → 큰 숫자 4개(기성률·계획 공정률·실제 공정률·공정차이) 한 줄 → 점검 현장 순위 → 선택 월까지 계획·실제 공정률 추이와 월별 기성 막대.
3. 점검 순위 한 줄: 현장 ID·이름, 계획 공정률, 실제 공정률, 공정차이, 기성률을 모두 표시하며, 누르면 비교표로 이동해 그 줄을 강조하고 펼침.
4. 비교표: 12개 현장의 지역·유형·당월 주요 공종·금액·공정·상태. 펼침 행에 공사기간·기록된 상황·대응 계획.
5. 단위: 금액은 백만원, 비율은 %, 공정차이는 pp이며 모두 소수 첫째 자리(예: 424,063.4 / 67.2% / −2.0pp).
6. 상태 구분: 정상(0pp 이상) / 주의(−5pp 초과·0pp 미만) / 점검(−5pp 이하)을 색과 글자로 함께 구분(색만으로 구분하지 않음).
7. 예시 숫자(2026-09 전체): 기성률 67.2%, 계획 73.2%, 실제 71.2%, 공정차이 −2.0pp. 점검 순위 D −10.7pp → I −7.6pp → K −5.4pp.
8. 자료가 없거나 계산할 수 없으면 0%가 아니라 "계산 불가"로 표시(예: 2025-10 당월기성액).
9. AI에게 묻기: 지금 범위 표시, 예시 질문 4개, 질문 입력, 답변과 기준 월·현장·근거 숫자·기록 필드. AI 연결이 실패해도 대시보드와 CSV는 계속 사용 가능.
10. 가져오기 오류 화면은 어느 행의 무엇이 문제인지 알려 주고 "지금 자료는 유지됩니다"라고 안내.
