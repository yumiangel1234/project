# 개발 계획 — 현장별 공정·기성 대시보드

## 한눈에 보기

- EPIC 3개, Story 11개입니다(실습조건: EPIC 3개 이하, Story 15개 미만). EPIC은 하나씩 만들고, 끝날 때마다 자동 검사와 브라우저 확인을 합니다.
- 순서: ① 자료 가져오기·필터·현황·추이 → ② 점검 현장·기록 펼침·CSV → ③ 근거를 보여 주는 AI 질의와 로컬 전체 검증.
- 모든 Story에 "브라우저에서 무엇을 해 보면 되는지"와 "화면에 무엇이 보여야 하는지"를 적었습니다.
- 마지막 Story(S11)에서 로컬 검증 결과를 보고하고 멈춥니다. GitHub 저장과 Vercel 배포는 Story가 아니며, 각각 사용자가 따로 요청한 뒤에만 진행합니다.
- 시작 전 상태: Node.js 설치 확인됨, 키 입력됨(동작 미확인), `design/` 시안 없음.

기준 문서: `실습조건.md`, `작업규칙.md`, `01_PRD.md`, `02_FRD.md`, `03_TRD.md`, `data/검산표.md`. 숫자는 검산표와 원본 CSV에서 가져왔으며, 앱이 실제로 이 값을 보여 주는지는 각 Story 확인에서 처음 확인합니다.

## 5. 별도 단계 — Story가 아닙니다

아래 두 단계는 개발 Story·완료 조건에 넣지 않았고 자동으로 실행되지 않습니다. S11이 끝나면 결과와 남은 작업을 보고하고 멈춥니다. "구현 완료", "확인했어요", "다음으로", "알아서 해 주세요"만으로는 시작하지 않습니다.

| 단계 | 시작 조건 | 포함하지 않는 것 |
|---|---|---|

| Vercel 배포 | 사용자가 STEP 11에서 직접 하거나, 배포할 프로젝트·저장소를 정해 별도로 요청한 경우에만 진행합니다. `GEMINI_API_KEY`는 배포 서버 환경 변수로 따로 넣습니다. | 요청 전의 프로젝트 생성·저장소 연결·환경 변수 등록·미리보기·운영 배포, GitHub 변경만으로 배포되는 자동 연동 |
